## 증거의 단계

**A. 코드에서 직접 확인한 것:** Git 트리에 있는 Java 파일의 실제 본문, 타입 선언, 찾을 수 있는 단일 행 필드 선언, 메서드 선언 후보, 코드 속 호출 식별자와 제어문 표현.

**B. 정적 추론:** 메서드 이름과 특정 구문을 이용한 역할 분류. 예를 들어 `update`를 '상태 갱신'으로 분류하더라도 실제로 어떤 상태를 바꾸는지와 분기·부작용을 모두 입증하지는 않는다.

**C. 추가 검증이 필요한 것:** 다중 행 선언/람다/익명 클래스 등 파서가 놓칠 수 있는 문법, 상속·인터페이스의 동적 디스패치, 전체 호출 그래프, 정확한 전투 공식, 세이브 호환성, Gradle 빌드/게임 실행, 스레드 경합과 성능.

**'모두 읽음'과 '모두 이해/검증됨'은 다름**. A의 전체 범위가 확보됐지만 B·C는 계속 코드 문맥 또는 실행 증거로 확인해야 한다. 코드는 수정하지 않고 문서만 추가했다.
